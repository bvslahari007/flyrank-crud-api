# Task API — CRUD Ops. (FlyRank W2 · A1)

A small to-do list API built with **FastAPI** as part of the FlyRank Backend AI Engineering internship. Supports full CRUD (Create, Read, Update, Delete) on an in-memory list of tasks, with interactive docs via Swagger UI.

## What this is

This API manages a simple in-memory to-do list. You can create tasks, list them, fetch one by id, update a task's title and/or completion status, and delete a task, the four CRUD operations, built stage by stage while learning the request/response loop from the server side.

Data is **in-memory only** it resets every time the server restarts. There's no database yet and comes in a later assignment.

## How to run it

Requires Python 3.10+.

```bash
git clone <https://github.com/bvslahari007/flyrank-crud-api>
cd first-crud-api
python3 -m venv venv
source venv/bin/activate
pip install fastapi uvicorn
uvicorn main:app --reload
```

The server starts on **http://localhost:8000**.

## Endpoints

| Method | Path              | Description                          |
|--------|-------------------|---------------------------------------|
| GET    | `/`               | Describes the API                    |
| GET    | `/health`         | Health check — confirms the server is alive |
| GET    | `/tasks`          | List all tasks                       |
| POST   | `/tasks`          | Create a new task                    |
| GET    | `/tasks/{task_id}`| Get a single task by id              |
| PUT    | `/tasks/{task_id}`| Update a task's title and/or done status |
| DELETE | `/tasks/{task_id}`| Delete a task                        |

## Example request

```bash
curl -i -X POST http://localhost:8000/tasks -H "Content-Type: application/json" -d '{"title":"Buy milk"}'
```

```
HTTP/1.1 201 Created
content-type: application/json

{"id":4,"title":"Buy milk","done":false}
```

## Notes

- Data lives only in memory — restarting the server resets it to the 3 seed tasks.
- Validation: `POST`/`PUT` requests with a missing `title` return `422` (FastAPI's built-in schema validation); requests with an empty-string `title` return `400` (custom validation in the endpoint).

## Database

This project now stores tasks in **SQLite** instead of an in-memory list.

**Why SQLite:** it requires no separate server or installation — the entire 
database is a single file (`tasks.db`), created automatically the first time 
the app runs. That makes it ideal for a small project like this: zero setup, 
and data survives server restarts.

**Where the database lives:** `tasks.db` in the project root. It's listed in 
`.gitignore`, so it's not committed to the repo — each fresh clone creates its 
own file automatically on first run, seeded with 3 example tasks.

**How to run:**
```bash
source venv/bin/activate
uvicorn main:app --reload
```
The `tasks` table and 3 seed tasks are created automatically on first launch.

**Example SQL query (run in DB Browser for SQLite):**
```sql
SELECT * FROM tasks WHERE done = 1;
```
This returned only the tasks marked as completed — confirming that `WHERE` 
filters rows based on a column's value, the same mechanism used by 
`WHERE id = ?` in the API's endpoints.
